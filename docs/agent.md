# Research Agent

`/chat` is a conversational console over every Underlying Analyzer capability. It
streams answers, renders charts inline as it generates them, and can publish a
saveable research brief with explicit recommendations.

## One registry, five surfaces

Every capability is declared once in [`app/tool_registry.py`](../app/tool_registry.py)
as a `ToolSpec`: name, group, summary, when-to-use guidance, JSON Schema, and the
public HTTP route that implements it. Everything else is generated:

| Surface | Generated by |
| --- | --- |
| `GET /api/docs` | `app/api_catalog.py` |
| `GET /api/openapi` | `app/openapi.py` |
| `POST /api/mcp` (streamable HTTP) | `app/mcp_http.py` |
| `underlying-mcp` (stdio) | `mcp_server/server.py` |
| The `/chat` agent | `app/agent.py` |

Adding a tool to the registry adds it to all five at once. A tool cannot
document behaviour its route does not have, because the registry only ever
points at real routes.

## Execution model

`app/tool_executor.py` runs every tool the same way: it resolves the spec into a
method, path, and body, then dispatches **in-process** through Flask's test
client. There is no second implementation of a tool and no network hop between
the agent and the API it calls.

Two transformations happen on the way back:

- **Artifact extraction.** Base64 images are lifted out of the JSON and replaced
  with short refs (`image_ref: "img_1"`). The model reads cheap refs; the browser
  receives the real bytes and renders them inline. A chart pack that would cost
  thousands of tokens costs a few dozen.
- **Compaction.** Long strings and long arrays are trimmed so one tool result
  cannot swamp the context window.

## Streaming protocol

`POST /api/agent/chat/stream` returns `application/x-ndjson`. One JSON object per
line:

| Event | Payload |
| --- | --- |
| `start` | `model`, `tools[]` |
| `text` | incremental assistant prose |
| `tool_call` | `id`, `name`, `title`, `group`, `cost`, `input` |
| `tool_result` | `id`, `name`, `ok`, `status`, `duration_ms`, `result`, `artifacts[]`, `error` |
| `article` | `article`, `markdown` |
| `error` | `message` |
| `done` | `stop_reason`, `text`, `tool_trace[]` |

The stream is padded with leading newlines to defeat proxy buffering; consumers
skip blank lines.

```bash
curl -N -X POST http://127.0.0.1:5050/api/agent/chat/stream \
  -H 'Content-Type: application/json' \
  -d '{"messages":[{"role":"user","content":"How does NVDA look this week?"}]}'
```

Requests may send `tools` plus `"tool_policy":"exact"` to require that exact,
non-empty set of recognized agent tools. Without the policy, tool selection
keeps the legacy best-effort behavior and falls back to the full registry when
none of the requested names are recognized.

`POST /api/agent/chat` runs the identical turn and folds it into a single JSON
response for non-streaming clients.

### Conversation replay

The browser stores plain `{role, content}` records plus a `tool_trace` array per
assistant turn. On the next request the trace is replayed as a compact line
rather than full tool blocks. Replay stays cheap, and a saved conversation can
always be resumed even after the tool registry changes.

## Articles

`compose_research_article` is a normal registry tool bound to
`POST /api/agent/article`. The agent calls it when a write-up is the right
deliverable; the route validates and normalizes the payload
([`app/articles.py`](../app/articles.py)) and returns both the structured article
and rendered markdown.

An article carries a thesis, ordered sections, recommendations (each with a
stance, an action, and an invalidation condition), risks, and sources. The chat
UI renders it as a card with Save, Copy markdown, and Download actions.

## Persistence

| Signed in | Storage |
| --- | --- |
| Yes | Supabase `agent_chats`, `agent_messages`, `research_articles`, owner-scoped by RLS |
| No | `localStorage`, migrated up once on first sign-in |

Saved messages keep artifact metadata but drop the base64 payload — a single
chart is roughly 200KB and would exhaust the localStorage quota within a few
conversations.

## Configuration

```bash
ANTHROPIC_API_KEY=sk-ant-...        # required; the agent is offline without it
ANTHROPIC_AGENT_MODEL=              # optional; defaults to ANTHROPIC_TEXT_MODEL
EXA_API_KEY=                        # optional; enables search_news
```

`GET /api/agent/tools` reports `agent_ready` so the UI can show the agent is
offline rather than failing on the first message.

## Safety

The registry contains no execution path — there is no broker integration, no
order route, and no write access to anything but the visitor's own saved
research. Recommendations are framed as research stances with reasoning and
falsification conditions, and every article carries a disclaimer.
